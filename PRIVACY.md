# Privacy

> **publik build.** This copy of Zenith is built from the fork https://github.com/Blueturboguy07/zenith and distributed by publik (https://publikhq.com/moodledesk). It differs from the original app (https://github.com/zac06/zenith) in three points: the desktop app opens with Sign in with publik, the desktop app sends usage counts to publik, and the desktop app does not check for updates or update itself. See "publik" below and [`PUBLIK-BUILD.md`](PUBLIK-BUILD.md). The original app has no sign-in and sends no usage counts.

Zenith runs on your computer. It has no accounts, no crash reporting and no servers of its own. The publik build asks you to sign in with a publik account, and sends the sign-in requests and the usage counts described below to publik. Nothing else is sent to the developer or to publik, and your Moodle data is not collected.

**What it stores on your computer**
- Your Moodle login token, in the system keychain.
- The files you download, in the folder you choose, and a list of those downloads in the app's data folder.
- Your settings (theme, download mode, download folder), in the app's local storage.
- A copy of the course pages, assignments and forum posts you opened, in the same local storage, so they stay readable offline. It is not encrypted, and signing out deletes it. Android does not include it in backups.

**Who it talks to**
- **Your Moodle site.** Everything you see (courses, files, grades, dates) and your login go there. With password login your username and password are sent to it. Only `https://` sites are accepted. Your site sees the requests as coming from a Moodle mobile app and may log them under its own privacy policy.
- **GitHub (`github.com`).** The About page shows the author's picture from it. The Android app also asks it for the latest version (the desktop app of the publik build does not). GitHub can see your IP address. The project website asks `api.github.com` for the same reason, to show the download buttons.
- **Images in course text** are shown only if they come from your Moodle site, so a teacher's pasted picture from another website is not loaded and cannot reveal your IP address. Cover images use the address your Moodle site provides.
- **Links** you click open in your browser. After that, the other website's own policy applies.
- **publik (`publikhq.com`), desktop app of the publik build only.** The files below are in the `publik` folder of your user account (macOS: `~/Library/Application Support/publik`, Windows: `%LOCALAPPDATA%\publik`, Linux: `~/.config/publik`).
  - **Sign in with publik.** At the first start, the app asks publik for a key for this computer (`POST /api/v1/installs`). The request holds: the app token of this build (it names the app, not you), the app name (`moodledesk`), the app version, the operating system (`macos`, `windows` or `linux`), the CPU type (`arm64` or `x64`), the name of the computer (as the `hostname` command shows it) and a random install ID for the key. publik answers with a key for this computer (`pk_...`) and a sign-in link. The app keeps the key, that install ID and the sign-in link in the file `apps/moodledesk.json` (on macOS and Linux only your user can read it). The button **Sign in with publik** opens the link in your browser, where you sign in to publik or make a publik account. publik then links this computer to your publik account. While the sign-in window is open, the app asks publik every 3 seconds, for at most 10 minutes, whether this computer is signed in (`GET /api/v1/wallet`, with the key). At each later start it asks once. The answer can hold your publik name and the state of your publik plan; the app does not keep them. The sign-in requests hold no Moodle site, no login, no course data and no file name. You cannot turn off the sign-in: Zenith from publik opens only after it.
  - **Usage counts.** After the sign-in, the app sends one small message when it starts and one every 30 minutes while it runs. The message holds: the app name (`moodledesk`), the app version, the operating system, the CPU type and a random install ID. The install ID is kept in the file `telemetry.json`. Other publik apps on the same account use the same ID. The message goes with the key of this computer, so publik links the count to your publik account. The message holds no Moodle site, no login, no course data and no file name. publik can see your IP address when the message arrives. It does not store the address with the count; its rate limiter keeps a hashed form for up to one day.
  **To turn off the usage counts:** set `DO_NOT_TRACK=1` (or `PUBLIK_TELEMETRY=0`) in the environment, or put `{"usage": false}` in the file `consent.json` in the `publik` folder. The app then sends no usage count and creates no `telemetry.json`. The sign-in stays on. Details: https://publikhq.com/skills/telemetry.md and https://publikhq.com/privacy

Questions or problems with the app: open an issue at https://github.com/zac06/zenith/issues. Questions about the publik build or its usage counts: https://publikhq.com/moodledesk (do not ask the original author).
